# Maya Chen · 后端 API 工作记录整理

## 项目理解 Agent 的整理说明

本日志依据上一阶段 Maya 的个人 Agent 协作记录整理，不复制原始对话。重点不是记录 AI 说过什么，而是呈现 Maya 如何检查、接受、修正或拒绝建议，以及这些判断怎样改变后端实现。

## 初始理解与变化

Maya 最初把目标定义为接入 `POST /api/orders`，让前端能够创建订单。随着实现推进，她把“完成”标准从接口可调用提高为：业务失败可区分、并发竞争只有一个赢家、订单数据可独立解释、局部失败不会破坏商品状态。

## Maya 对 AI 内容的判断

- 没有接受“路由能返回订单就算完成”。她要求补齐自购、商品不存在、商品不可售和输入不合法等业务边界。
- 质疑“先查询商品再更新”的直观写法。她识别出两个请求会同时读到 `available`，转而要求条件更新。
- 质疑“只返回 orderId/itemId”。她判断成功页需要订单事实，因此要求当前响应至少包含标题和价格快照；币种字段留待跨节点契约统一。
- 主动发现 `sold` 与“等待卖家确认”的语义冲突。她同意 `reserved` 更准确，但拒绝在本次联调中顺带扩展取消、超时和恢复流程。
- 没有把 Mock 单元测试通过等同于事务已验证。她保留真实 PostgreSQL 回滚和并发测试为上线前风险。

## 关键决策如何影响产出

| Maya 的判断 | 对产出的影响 |
|---|---|
| 业务失败必须稳定分类 | API 使用稳定错误码，前端不依赖自由文本 message |
| 并发判断应原子化 | 仓储层使用带状态条件的更新 |
| 订单是新领域事实 | 当前接口返回商品标题与价格快照，并记录币种字段待统一 |
| 不隐藏状态语义债务 | README、数据库注释和协作记录显式说明 sold 的限制 |
| 测试结论必须有边界 | 单元测试结论与数据库集成测试风险分开记录 |

## 被拒绝或暂缓的扩展

- 本次不引入完整 `reserved` 状态机。
- 本次不扩展支付、取消、退款和物流。
- 本次不把测试替身的通过结果包装成真实事务验证。

这些不是遗漏，而是 Maya 为保持联调范围可验证所做的主动取舍。

## 当前验证结论

上一阶段已有后端实现与单元测试记录支持主要服务分支。当前仍未证明真实数据库在订单插入失败时一定回滚商品状态，也未完成两个并发购买请求的集成验证。进入真实开发前，应把这两项作为阻塞检查。

## 建议进入项目长期记忆

1. 创建订单不是单路由问题，而是业务边界、并发和事务共同构成的能力。
2. 前端只依赖稳定错误码，错误 message 可变化。
3. 创建接口返回新领域对象的关键快照；当前已有标题与价格，币种仍需统一。
4. `sold` 暂代锁定状态，后续必须以 `reserved` 及其退出路径偿还。
5. 测试结论必须说明 Mock、数据库和并发各自覆盖了什么。
