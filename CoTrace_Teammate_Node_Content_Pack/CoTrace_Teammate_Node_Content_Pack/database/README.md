# 队友 B：数据库设计与实现

> 队友 B 是演示代号，不是最终成员姓名。界面必须根据项目协作者配置动态替换负责人信息。

本目录提供二手交易最小闭环所需的 PostgreSQL 结构与事务示例。当前演示只覆盖“创建订单并锁定商品”，不扩展支付、物流、取消和退款。

## 文件顺序

1. `sql/001_create_users_items.sql`
2. `sql/002_create_orders.sql`
3. `sql/003_add_order_constraints.sql`
4. `sql/create_order_transaction.sql`
5. `sql/seed_demo_data.sql`（可选演示数据）

## 关键约束

- 订单保留商品标题和价格快照，历史展示不依赖商品后续修改。
- 商品状态更新使用条件更新；只有 `available` 商品能进入本次交易。
- 商品状态更新和订单写入处于同一事务，任一步失败都应回滚。
- 当前将创建订单后的商品临时标记为 `sold`，但页面文案仍是“等待卖家确认”。这是 MVP 的已知语义折中；后续应新增 `reserved`，不能在当前节点里悄悄扩大范围。

## 调用约定

后端应在单个数据库事务中调用 `create_order_transaction`。函数返回空集时，表示商品不存在、不可售或发生并发竞争；后端再根据业务上下文映射为稳定错误码。
