# 校园二手交易平台：项目需求与范围说明

版本：v1.0  
负责人：Maya Chen  
关联节点：产品与需求分析  
状态：团队已确认

## 1. 项目目标

为校内学生提供轻量的二手物品发布与交易协商流程。当前课程 Demo 关注团队能否共同理解“发布商品—发起购买—卖家确认—完成交易”这条核心链路，以及 AI 参与代码生产后，团队如何查看依据、讨论限制并完成人工验证。

## 2. 核心用户

- 卖家：发布闲置物品，查看购买申请并决定是否确认交易。
- 买家：浏览可售商品，发起购买申请并查看订单状态。
- 项目成员：分别负责需求、数据库、后端、前端、联调和测试。

## 3. 本阶段功能范围

### 包含

- 商品发布与基础信息展示；
- 买家创建订单；
- 卖家与买家身份记录；
- 订单进入“等待卖家确认”；
- 商品停止接受新的购买申请；
- 自购与商品不可售错误处理；
- 订单保存交易发生时的商品标题与价格；
- API 错误码供前端展示明确提示；
- 主要正常与异常路径测试。

### 暂不包含

- 在线支付、退款与资金托管；
- 物流与线下交付管理；
- 完整库存锁定系统；
- 卖家拒绝后的自动恢复流程；
- 消息通知；
- 用户信用与争议仲裁；
- 真实数据库事务。

## 4. 关键业务规则

1. 用户不能购买自己发布的商品。
2. 只有 `available` 商品可以创建订单。
3. 同一商品最多允许一个购买请求成功占用。
4. 创建成功的订单状态为 `pending_seller_confirmation`。
5. 当前 Demo 将商品改为 `sold`，其临时语义是“停止接受新的购买申请”。
6. 订单保存商品标题与价格快照，保证历史记录不随商品修改而变化。
7. 订单写入失败时，Demo 尝试恢复商品；真实系统需使用数据库事务。

## 5. 成功标准

- 后端 API 能清晰返回成功结果和业务错误；
- 前端能根据错误码展示用户可理解的提示；
- 测试覆盖成功、自购、商品不存在、商品已售出和竞争购买；
- AI 提出的修改需由负责人确认；
- 队友只能看到已提交代码及负责人选择公开的 AI 溯源；
- 当前限制在代码提交和共享文档中可追溯。

## 6. 当前未决问题

- 后续是否增加 `reserved` 状态；
- 卖家拒绝后如何恢复商品；
- 真实数据库使用何种事务和并发控制；
- 订单取消、超时和通知由哪个节点负责。
