## 1. 联调目标

确保商品详情页的购买操作、创建订单接口和结果反馈使用同一套状态与错误语义。

## 2. 页面与接口关系

| 页面动作 | 接口 | 成功结果 |
|---|---|---|
| 点击“申请购买” | POST /api/orders | 进入等待卖家确认页面 |
| 创建中 | 同一请求 | 操作键禁用并显示处理中 |
| 创建失败 | 同一请求 | 留在当前页并显示对应提示 |

## 3. 错误码映射

| API code | 用户提示 | 页面动作 |
|---|---|---|
| INVALID_ORDER_INPUT | 页面信息不完整，请刷新后重试 | 保留当前页 |
| ITEM_NOT_FOUND | 商品不存在或已被删除 | 提供返回列表入口 |
| SELF_PURCHASE_NOT_ALLOWED | 不能购买自己发布的商品 | 保留商品详情 |
| ITEM_NOT_AVAILABLE | 商品已被其他买家购买 | 刷新商品状态并返回列表 |
| ORDER_CREATE_FAILED | 订单创建失败，请稍后重试 | 恢复操作键，允许重试 |
| INTERNAL_ERROR | 服务暂时不可用，请稍后重试 | 恢复操作键，允许重试 |

## 4. 前端交互要求

- 请求发出后禁用购买操作键，避免用户连续点击；
- 禁用操作键不能代替后端防重复成交；
- 失败时不得跳转成功页；
- 错误提示使用 API `code` 映射，不直接展示服务端内部细节；
- 成功页显示订单快照中的标题与价格；
- 成功页明确显示“等待卖家确认”。

## 5. 需要共同验证的场景

1. 正常买家购买可售商品；
2. 卖家尝试购买自己的商品；
3. 商品详情打开后，商品被另一买家买走；
4. 用户快速连续点击购买操作键；
5. 订单服务返回 500；
6. 商品标题在订单创建后被修改，历史订单仍显示原快照。
