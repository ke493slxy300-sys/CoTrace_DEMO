# Cursor 接入说明：SeatFlow 一页项目日志

## 本阶段只做什么

1. 在项目列表增加一张 SeatFlow 虚构已完成项目卡片。
2. 点击“查看项目日志”进入一页式项目记忆层。
3. 页面读取 `project/seatflow-project-log.json`。
4. 保持现有暗色视觉系统，并参考线框图的“左侧决策历史 + 右侧两张总结卡”结构。

不要把本内容包扩成新的历史项目代码仓，也不要实现真正的跨项目搜索、智能检索或模型总结。

## 项目列表卡片

数据来自 `project/seatflow-project-card.json`。

- 必须显示“已完成”。
- 必须显示“CoTrace Demo 虚构历史项目”。
- 主要按钮是“查看项目日志”。
- 不显示“进入工作区”“继续开发”或“提交”。
- 队友 A/B/C 是历史演示代号，不是最终成员名称。

## 一页日志结构

### 顶部

- 返回项目列表。
- 标题“项目记忆层”。
- 项目名 SeatFlow。
- 搜索框只做前端本地过滤。
- 三个建议关键词只过滤三条决策记录。

### 左侧主区域

渲染三条 `decisionHistory`：

- 日期
- 标题
- 问题
- 讨论
- 决策
- 理由
- 四类证据入口

证据入口在当前阶段没有真实文件时可以显示 Toast：“Demo 记录，未附加原始文件”。不得跳到 CoTrace 当前校园交易项目的代码。

### 右上

渲染 `personalGrowth`。

- 标记“私密”。
- 仅当前体验身份 Maya 可见。
- 不应被搜索或团队项目总结引用。

### 右下

渲染 `agentSummary`：

- AI 提供了哪些帮助
- 人类作出了哪些决定
- 重要工程经验
- 底部显示“AI 提供整理建议，人类确认哪些内容成为项目经验”。

## 提交与未提交边界

接入当前 CoTrace 项目时必须读取 `meta/content-state-map.json`，不要只根据文件是否存在判断其是否公开。

特别注意：

- Backend Pack 中存在完整 Agent 对话，不代表它已经提交。
- Maya 工作日志文件存在于 reserve，不代表当前 UI 应显示它。
- Teammate Pack 是预置共享种子，不应伪装成体验者刚刚执行的提交。
- 体验者确认提交后，只公开其勾选的代码和溯源。
- 体验者确认任务完成，只改变蓝图状态。
- 讨论归档后生成的 Agent 草案仍不是正式团队决定。
- 只有人工确认的团队决定才可以进入项目日志决策历史。

## 当前 CoTrace 开发日志

`development/CoTrace_开发日志.md` 是开发交接材料，不默认渲染为 SeatFlow 项目日志内容。它用于 Cursor 判断当前哪些功能已经完成、哪些只是方案确认。

不要把“设计已确认”自动改写成“代码已完成”。完成实现并验证后，才能更新对应 `implementationStatus`。

## 推荐路由与组件

请适配项目现有路由，不强制使用以下命名：

- `ProjectListPage`：增加 SeatFlow 卡片。
- `ProjectLogPage`：一页项目日志。
- `DecisionHistoryCard`：三条决策历史。
- `PersonalGrowthCard`：私密成长档案。
- `AgentProjectSummaryCard`：项目理解 Agent 总结。

只新增必要组件，不复制新的全局导航和页面壳。

## 验收

- 项目列表出现 SeatFlow，状态为已完成。
- 点击“查看项目日志”进入一页日志。
- 返回按钮回到项目列表。
- 三条决策历史完整显示。
- 搜索和建议关键词能过滤决策。
- 个人成长卡显示私密提示。
- Agent 总结明确区分 AI 帮助和人类决定。
- 页面不存在进入工作区、提交或编辑代码入口。
- 未提交内容没有进入项目日志。
- 不修改当前项目蓝图、节点、提交和讨论状态。
- `npm run build` 通过。
